A request waiting out a retry's back-off now answers to its `signal`, ending with `RequestAbortedError`, and to `stop()`, ending with `ClientUnavailableError` `handler_stopped`; either way the queue entry it kept is released, and a retry is never sent upstream after `stop()` has returned. An OAuth2 token refresh times out after the client's axios `timeout` or 30 seconds, whichever is shorter, so a client with no `timeout` or one above 30 seconds gets 30, and a request whose `signal` aborts while it waits on one stops waiting without cancelling the refresh for the requests coalesced onto it.

A queued request whose cost cannot be spent is failed and stepped over rather than blocking its client's queue. A peer registration that cannot be parsed is skipped by role election rather than failing it. `redactUrl` hides a password containing an unencoded `@`, `#` or `?`, redacting when userinfo cannot be told apart from a port followed by a query, and stored credentials are decrypted only against a full-length authentication tag.

A thaw probe now succeeds on any response that would not itself freeze the client — a 404 or a 400 included — and fails only on a 429, a 5xx, a dropped connection, or a failure `retryOptions.classifyError` freezes on. A probe used to need a 2xx, though a plain 4xx shows the upstream has stopped limiting just as well.

`stop()` finishes within its documented budget even when the backend stops answering — about 27 seconds at the defaults, inside Kubernetes' 30-second grace period — and leaves no peer-heartbeat timer holding the process open. A SIGTERM, SIGINT or SIGHUP once again ends the host process after the drain: the signal is re-raised once `stop()` finishes unless the host listens for it itself, and a second signal during `stop()` exits at once.

A thaw probe counts only when the upstream actually answers: a response that would not freeze the client is a success, one that would is a failure, and a probe that was aborted, abandoned before dispatch, refused at connect or reset makes no progress either way. A request declined by a freeze no longer waits out its admission timeout when a confirmation reply is lost, and a stale admission pass no longer frees the concurrency slot of a stream that is still running.

BREAKING: once `stop()` has finished, `handleRequest` and the template mutations refuse with `ClientUnavailableError` `handler_stopped` rather than starting the handler again; call `start()` to bring it back. A template name that is empty or contains whitespace is refused with `invalid_template_name`, and a sub-client name that is empty or contains `:` or whitespace with `invalid_client_name_segment` — rename any that collided once backend keys normalized whitespace to `_`. An empty or blank `requestName` is refused with the new `ConfigurationError` code `invalid_request_name`. A handler `key` shorter than 32 characters is refused with the new `ConfigurationError` code `key_too_short`, since it is what every stored credential is encrypted under; a new key cannot read what the old one stored, so after changing it add every template client again.
